# Book Club Mini App

## Назначение
Мини-приложение книжного клуба для фронтендеров на React. Данные подтягиваются из
GitHub-репозитория `book-club-data` (организация `bookclubit`) через `raw.githubusercontent.com`.

## Стек
- React 18, TypeScript, Vite
- Tailwind CSS v4 (конфигурация CSS-first через `@theme` в `src/index.css`, без `tailwind.config.js`)
- React Router v6 для навигации
- SWR для fetching и кеширования
- Прогресс (SM-2), колода и статистика — в D1 бота (API Worker-а); localStorage —
  гостевой режим и кэш

## Структура
- `src/pages/` — страницы приложения (Home, Book, Chapter, Study)
- `src/lib/` — утилиты: `api.ts` (URL-хелперы + fetcher), `format.ts` (плюрализация, даты), `storage.ts` (SM-2 и прогресс)
- `src/types.ts` — общие типы
- `src/components/` — переиспользуемые компоненты (`Icon.tsx` — единственный источник иконок)

## Маршруты
- `/` — Home (книги со статусом `reading` + встречи)
- `/books` — Books (все книги с прогрессом чтения)
- `/book/:bookId` — Book (`bookId` = имя папки книги, напр. `docker-up-and-running`):
  обложка с кнопкой «в колоду» под ней (на мобильном обложка по центру и крупнее,
  кнопка — во всю ширину) и **все главы с темами на одной странице**
  (счётчика «разобрано N из M» в шапке нет — убран в августе 2026 вместе со
  шкалой: прогресс виден по книге в каталоге, а страницу он только перегружал)
  (глав бывает больше десятка, поэтому сверху — фильтр-«таблетки» по главе,
  по умолчанию «Все главы»). Колонка узкая (`max-w-3xl`): в широкой строка темы
  растягивается и её части разъезжаются по краям. Якоря — `#<slug главы>` и
  `#<id темы>` (на них ведёт профиль спикера)
- `/author/:authorId` — Author: все книги автора. Каталога авторов в данных нет
  (автор живёт в `meta.json` своих книг), поэтому список считается из уже
  загруженных мет — `collectAuthors` в `lib/authors.ts`, ключ SWR тот же `books`
- `/book/:bookId/chapter/:chapterId` — **своей страницы у главы нет**: маршрут
  оставлен редиректом на `/book/:bookId#<chapterId>`, чтобы старые ссылки из
  чатов и закладок не терялись
- `/meetings` — Meetings: таймлайн встреч. **Прошедшая встреча уходит в архив
  сама — через 4 часа после начала** (`isArchived` в `lib/events.ts`, единое
  правило: вкладки, ближайшие встречи на главной, карточка встречи, слоты тем,
  профиль спикера). Флаг `finished` админа остаётся — им можно убрать встречу
  раньше (отмена, перенос), но ждать его не нужно. То же правило и тем же
  числом часов — в боте (`lib/events.ts`, `eventArchived`) и CMS
  (`lib/events.ts`). Разделы «План» и «Архив» — вкладки
  (`components/Tabs.tsx`), внутри фильтры по книге и году (`components/FilterPills.tsx`);
  порядок списка — тихой кнопкой-переключателем у правого края вкладок (состояний
  два, пара «таблеток» ради этого читалась как ещё один фильтр).
  **На мобильном таймлайна нет**: колонка с датой съедала треть ширины, поэтому
  там дата — строкой над карточкой, а карточка во всю ширину; засечки и рельс
  включаются с `sm`. Дату и время карточка показывает в правом верхнем углу,
  но в таймлайне (проп `dateOutside`) остаётся только время — дважды на одном
  экране дата не нужна. По умолчанию в плане сверху
  ближайшие, в архиве — последние прошедшие; при смене вкладки фильтры
  и порядок сбрасываются (у плана и архива разные книги и годы).
  Кнопки «Стать спикером» здесь нет (убрана в июле 2026) — вход в `/join`
  остался на главной, строкой в вводном блоке (баннер-призыв убран в августе
  2026: на главной уже есть встречи и книги, второй призыв перетягивал
  внимание на себя)
- `/study` — StudyIndex, сверху вниз: календарь активности (вошедшим), кнопка
  «Начать повторение» — общая сессия по всем книгам колоды, и книги
  (`components/BookMastery.tsx`): одна карточка на книгу — прогресс, число
  карточек и сколько к повторению; нажатие запускает повторение этой книги.
  Гостю — предложение войти, вошедшим внизу — блок о напоминаниях бота.
  Сюда ведут «Открыть карточки» и «Подробная статистика» бота
- `/study/all` — Study без книги: **общая сессия** — карточки к повторению из
  всех книг колоды вперемешку, над карточкой подписана её книга. Сюда ведёт
  кнопка «Повторить карточки» в напоминании бота и в `/today`: человек сразу
  попадает в повторение, а не в список книг
- `/study/:bookId` — Study: карточки одной книги по порядку
- `/account` — профиль: вход (через бота) и **доклады человека** — «Следующий
  доклад» (взятая тема будущего эфира со статусом заявки,
  `collectUpcomingTalks`, слева обложка книги) и «Ваши доклады» (состоявшиеся — тот же
  `collectSpeakerTalks` и тот же список `components/TalkList.tsx`, что
  в публичном профиле спикера). Кто «я» как спикер, отвечает бот
  (`/api/membership`). Не участнику — карточка со статусом заявки и ссылкой
  на `/join`. «Ваши доклады» показывают **пять последних**, остальные — под
  «Показать все N докладов»; вместе со списком открываются фильтры по книге
  и году (`FilterPills`; правила фильтра — `talkFilterOptions`/`filterTalks`
  в `lib/speakers.ts`, общие с профилем спикера). Карточек и статистики здесь
  нет (перенесены на `/study`
  в октябре 2026) — только ссылка туда
- `/join` — BecomeSpeaker: «Стать спикером» целиком в приложении. Требует входа
  через Telegram. Участнику клуба показывает свободные темы плана с кнопкой
  «Взять тему» (`POST /api/claim` бота), новому человеку — форму заявки на
  участие (имя + рассказ о себе, `POST /api/membership`). Состояние общее
  с ботом (D1), поэтому продолжить можно где удобно

## Источник данных
База: `https://raw.githubusercontent.com/bookclubit/book-club-data/main/`
- `books/{folder}/meta.json` — мета книги; `authors` — объекты `{id, name, avatar, url}`,
  где `id` связывает книги одного автора (ключ маршрута `/author/:authorId`;
  у старых записей выводится из аватарки — `authorKey` в `lib/authors.ts`);
  `id` книги в meta может отличаться от имени папки, маршруты строятся по имени папки
- `books/{folder}/chapters/{chapterSlug}/chapter.json` — глава целиком, вместе с темами:
  `topics: [{id, title, speakers[], video_youtube, video_vk, presentation, resources[]}]`.
  У темы нет ни отдельного файла, ни текста: в UI это название, иконка с именем
  спикера и ссылки на материалы иконками (`components/TopicRow.tsx` — тема
  занимает одну строку списка, а не карточку: показывать больше нечего).
  У главы **нет** ни описания, ни `learning_outcome` — поля убраны из данных и CMS
  (июль 2026): главное в главе — её темы, и ради двух абзацев не стоило отдельного
  экрана. Не возвращать. Главы
  выводятся на странице книги секциями (`components/ChapterTopics.tsx`): заголовок
  «Глава N + название + число тем», под ним темы строками. Без карточек и рамок:
  главы держит воздух между секциями и линия под заголовком.
  **Спикер и ссылки темы приходят из трёх мест** (`topicMaterials` в
  `lib/materials.ts`): что вписано в саму тему (`speakers`, `video_*`,
  `presentation`), спикер и слайды из подтверждённой заявки в D1 и монтажный
  ролик доклада из `recordings` встречи. Иначе страница книги молчала о
  докладе, который в профиле спикера уже виден. Заявка учитывается, **только
  когда эфир прошёл** (`isArchived`) — бронь будущей темы не превращает строку
  в состоявшийся доклад; ссылка на слайды показывается после мержа PR доклада
  (`fetchPublishedSlides`, как в карточке встречи).
  Имена спикеров сводятся через реестр (`dedupeSpeakers`): в главе человек
  записан как придётся («Антон»), в заявке — полным именем, и без этого один
  спикер попадал в строку дважды.
  Встречу темы ищет `findTopicEvent` — по явному списку тем эфира, иначе по
  главе. **По одной книге не ищем**: так тема будущей главы прилипала к давней
  встрече той же книги и попадала в профиль спикера с чужой датой.
  На узком экране название главы занимает всю ширину, а второй строкой уходят
  только ссылки (доска, записи): число тем остаётся в строке заголовка — это
  его подпись, а не материал.
  **Темы с общим `talk_group` — один доклад** (`lib/topics.ts`): на странице
  книги они остаются отдельными строками (у каждой свой якорь `#<id темы>`),
  но собраны в блок с чертой слева, а материалы доклада стоят по центру блока
  под названиями с подписью «один доклад» — иначе ссылки читались бы как
  материалы последней темы. Везде, где тема = слот доклада (программа встречи,
  свободные темы плана, профиль спикера), группа склеена в одну тему
  с названием через запятую — это делает `mergeTalkTopics` прямо в загрузке
  (`fetchEventChapterTopics`, `fetchAllChapters`), поэтому бронь, слайды
  и запись у доклада одни.
  **Главы сворачиваются**: заголовок — кнопка (`aria-expanded`), по умолчанию
  все раскрыты (страница книги — про темы, а не про оглавление). Стрелка
  вынесена из потока на левое поле (`absolute -left-4 sm:-left-6`, по ширине
  полей страницы): в потоке она сдвигала заголовок вправо, и он переставал
  быть вровень с названиями тем. Свёрнутые
  главы хранит страница книги, а не сама глава: переход по якорю темы
  (`#<id темы>` из профиля спикера) раскрывает нужную главу, иначе прокручивать
  было бы не к чему.
  Справа в заголовке главы — иконка-ссылка на **доску обсуждения**
  (Excalidraw, Miro или скриншот). Доска хранится не в главе, а во встрече
  (`notes_board_url` открытого обсуждения), поэтому страница книги грузит
  встречи (ключ SWR `events`, общий с главной) и сопоставляет их с главами
  по `book_id` (через `bookFolderById`) и `chapter`. Доска — у главы, а не
  у темы: на обсуждении её рисуют на всю главу. Там же — **записи трансляций**
  прошедших встреч по главе (`chapterBroadcasts`). Встреч по главе бывает
  несколько (главу делят на части, обсуждение и доклады — разные вечера):
  одна — две обычные иконки, несколько — группировка по площадке
  («▶ 1 2 3   vk 1 2 3»), где логотип служит меткой, а номера частей —
  ссылками с датой в подсказке. Шесть одинаковых логотипов подряд читались
  как каша
- `books/{folder}/flashcards.json` — карточки (может отсутствовать — тогда 404 трактуется как пустой список).
  У карточки есть необязательный `example` — пример к ответу; показывается на
  обратной стороне под ответом моноширинным блоком (`components/FlashCard.tsx`).
  Если `example_kind: "note"` — это пояснение прозой: оно спрятано под словом
  «Объяснение» (текст по центру со стрелкой под ним, без рамки кнопки), по
  нажатию карточка раздвигается (класс `.expand`). Текст
  карточки — по левому краю, не по центру
- `events/closed-chapters/*.json` и `events/live-talks/*.json` — встречи клуба.
  Файла из реестра может уже не быть: перенос даты переименовывает файл,
  а реестр догоняет после мержа. Такая встреча (404) пропускается
  в `fetchEvents`, а не роняет список целиком.
  **Программа эфира — блоками** (`program: [{book_id, chapter, topic_ids}]`):
  за вечер разбирают несколько глав и даже книг. Разбирает её `eventProgram()`
  в `lib/events.ts` — у старых встреч книга и глава лежат прямо в событии, это
  тот же единственный блок; книги встречи даёт `eventBookIds()` (по ним же
  работает фильтр на `/meetings`). В карточке встречи темы разных глав
  разделены надзаголовком, у эфира по одной главе подписи нет
- Пути к изображениям в данных относительные (`/media/...`) — оборачивать в `mediaUrl()` из `api.ts`

`raw.githubusercontent.com` не умеет листать директории, поэтому список книг
(с главами), событий и спикеров приложение берёт из единого реестра
`index.json` в корне book-club-data (`fetchIndex()` в `api.ts`, кэш на сессию).
Реестр генерируется Action-ом в book-club-data после каждого мержа — контент,
добавленный через CMS, появляется в miniapp без правок кода.

В реестре (`version: 2`) главы книги — объекты `{slug, order, title, topics}`,
где `topics` — число тем. Попадают **все** главы с `chapter.json`, включая
пустые заготовки: глава видна сразу после создания.

Прогресс чтения книги (`readingProgress` в `api.ts`) считается как доля
разобранных глав (`topics > 0`) от `total_chapters` из meta.

**Доклады спикера — из двух источников** (`collectSpeakerTalks` в
`lib/speakers.ts`), иначе профиль расходится со страницей книги:

- заявки в D1 (`/api/claims`) — свежие брони: слайды из заявки, монтажный ролик
  из `event.recordings`, статус «заявка» до подтверждения админом;
- темы глав из `chapter.json` (`fetchAllChapters`, ключ SWR `chapters-all`) —
  так записаны все прошлые доклады: спикер в `topic.speakers` (по имени или
  алиасу), ссылки в самой теме. Событий за старые главы в клубе не заводили,
  поэтому у таких докладов **нет даты** — они идут после датированных, по номеру
  главы, и в карточке подписаны «Глава N».

Тема, попавшая в оба источника, показывается одной карточкой (ключ — `topic.id`):
ссылки из данных клуба дополняют заявку. Доклад виден, только если он состоялся:
есть материалы либо встреча прошла. Список спикеров считает доклады тем же
`collectSpeakerTalks` — счётчик на карточке не должен расходиться с профилем.

## Колода карточек
Колода хранит **подписки**, а не список карточек: новые карточки подписанной
книги подхватываются сами. Подписка оформляется кнопкой под обложкой книги
(`components/AddBookToDeck.tsx`) — на книгу целиком. Отдельные подписки на
главу (`deck.chapters`) только читаются: страницы главы больше нет, но у кого
такие подписки уже есть — повторение по ним работает.

**Колода общая с ботом** (сентябрь 2026). Раньше она жила только
в localStorage, а бот слал карточки по всем книгам — человек с пустой
колодой получал их каждый день. Теперь у вошедших колода в D1 бота
(`GET/POST /api/deck`), и бот утром напоминает только о картах колоды —
с кнопкой, открывающей общую сессию `/study/all` прямо в Telegram. Карточек в чат бот больше
не шлёт: повторение — только здесь.

- Кто читает колоду — `lib/useDeck.ts` (SWR `deck:<id>` / `deck:guest`):
  вошедшим — с сервера (localStorage — кэш), гостям — localStorage.
  Изменения оптимистичные, сервер отвечает колодой после изменения.
  `lib/deck.ts` — гостевое хранилище и чистые хелперы (`bookCardScope`,
  `cardsInScope`, `withBook`…).
- **Первый вход на устройстве** (`lib/sync.ts`, из `AuthProvider`): колода
  и прогресс гостевого режима переносятся в аккаунт (`merge` колоды,
  `POST /api/progress/import` — сервер не трогает карточки, которые уже знает).
  Один раз на устройство и аккаунт (`bc-synced:<id>`): дальше localStorage —
  только кэш, и убранное на другом устройстве не вернётся.
- «К повторению» в самой сессии (`Study`) у вошедших считается по серверному прогрессу
  (ключ SWR `server-progress:<id>`, общий со Study) — те же цифры, что
  в напоминании бота.

## Статистика
На вкладке «Карточки» (`/study`) — `GET /api/stats`, ключ SWR `stats:<id>`.
**Считает бот** (`lib/stats.ts` там) — те же цифры в его `/status`
и напоминании, здесь только показываем. Сверху календарь активности за
12 недель (`ActivityHeatmap`: столбец — неделя, строка — день недели; дни — по
Москве), ниже книги (`BookMastery`: доля выученного, полоса «выучено / изучаю /
новые» — цвета частей в `lib/mastery.ts`, общие для полосы и легенды, — число
карточек и «N к повторению»). Выучена — карточка с интервалом от 21 дня.
Журнал повторений бот ведёт с сентября 2026, раньше календарь пуст.

**Сводки с цифрами нет** (серия дней, «вспоминаешь» и т. п. — убрана в октябре
2026, не возвращать): она дублировала карточки книг. Эти цифры остались
в `/status` бота. Отдельного списка «книги колоды» тоже нет — он слит
с освоением в одну карточку книги: раньше одна книга показывалась на странице
дважды.

Гостю (и когда бот недоступен) карточки книг считает приложение по прогрессу
с устройства — `localBookStats` в `lib/mastery.ts`, правила те же, что у бота.
Календаря у гостя нет: журнал повторений ведёт только бот.

## Вход
Внутри Telegram — автоматически по initData Mini App. В браузере — **через
бота**, без номера телефона (`components/TelegramBotLogin.tsx`): страница
заранее получает `code` + `secret` (`POST /api/auth/bot`), кнопка — обычная
ссылка `t.me/bookclubfrontbot?start=login_<code>` (так надёжнее всего
открывается приложение Telegram на телефоне), человек жмёт в боте «Войти»,
страница опрашивает `/api/auth/bot/check` и сразу проверяет при возвращении
на вкладку. Telegram Login Widget убран: он подтверждает вход сообщением от
Telegram по номеру телефона, и в России оно не доходит.

## Телеграм-бот
Бот клуба — `@bookclubfrontbot` (репозиторий `book-club-bot`, Cloudflare Workers).
Заявка на участие и выбор темы доклада живут в приложении (`/join`) — в бота
не перекидываем; `speakerUrl()` остаётся вторичной ссылкой «то же самое в боте».

**Темы докладов берут только участники клуба.** Кто участник, решает бот
(`GET /api/membership`): каталог `speakers.json` по Telegram-нику или одобренная
админом заявка. Новый человек может ходить на встречи и учить карточки сразу,
а темы открываются после одобрения заявки.

## Дизайн-система
- Токены только в `@theme` в `src/index.css`: цвета в oklch (тёплая «бумажная» палитра), радиусы `rounded-card`/`rounded-btn`, тени `shadow-card`/`shadow-lift`
- Две темы: светлая (по умолчанию) и тёмная — переопределение токенов под `[data-theme="dark"]` в `index.css`; переключатель `components/ThemeToggle.tsx`, выбор в `localStorage('theme')`, инит-скрипт против мигания — в `index.html`. Новые цвета добавлять сразу в обе темы
- Текст на акцентном фоне — токен `on-accent` (не `text-white`); блоки кода — токены `terminal`/`terminal-ink` (тёмные в обеих темах)
- Один акцентный цвет — терракота (`accent`); семантические `success`/`warn`/`danger` с мягкими `-soft`-фонами
- Шрифты: `font-display` (Source Serif 4) для заголовков и названий, Golos Text — текст и UI; подключены в `index.html`
- Иконки — только inline-SVG через `components/Icon.tsx` (фирменные глифы соцсетей —
  `components/BrandIcon.tsx`); эмодзи в UI не использовать
- Ссылка внутри строки текста — класс `.link-inline` (подчёркивание, а не цвет):
  цветное слово посреди абзаца в тёплой палитре читается как сбой вёрстки
- Ссылки на материалы (запись, слайды, доп. ссылка) — иконками без подписей:
  общий `components/MaterialLinks.tsx` и класс `.icon-link`, смысл несёт
  `aria-label`/`title`. Один и тот же доклад показывается и в главе, и в профиле
  спикера — набор иконок обязан быть общим
- Повёрнутый (вертикальный) текст не использовать: пробовали так подписывать главы
  на странице книги — читается плохо и выглядит чужеродно
- Разделы страницы переключать вкладками (`Tabs.tsx`, подчёркивание активной),
  а фильтры внутри раздела — «таблетками» (`Pill.tsx`): разный смысл должен
  выглядеть по-разному. «Таблетка» не бывает шире своего ряда (длинное название
  книги обрезается многоточием). Длинный ряд значений фильтра — через `FilterPills.tsx`:
  одна строка, что не влезло — под «…» (порядок значений задаёт, что останется
  на виду: свежие годы, читаемые сейчас книги)
- **Значение фильтра, по которому нечего показать, не выводится** — например,
  категория книг без книг (`countBy(c.id) > 0` в `pages/Books.tsx`). Это
  осознанно: пустая «таблетка» ведёт в пустой экран. Категории каталога —
  `BOOK_CATEGORIES` в `types.ts`, у языков есть короткая подпись `short`
  («JS», «TS»), полное название уходит в `title`
- Карточками оборачивать только самостоятельные объекты (книга, встреча, спикер).
  Группы внутри страницы (главы книги) разделять воздухом, надзаголовком-«бровкой»
  и линиями — рамка на каждую группу превращает страницу в набор коробок
- Анимации: каскадное появление через класс `.reveal` и CSS-переменную `--reveal-delay`; hover-переходы 0.2–0.3s; обязательно уважать `prefers-reduced-motion` (уже в `index.css`)
- Не использовать произвольные значения (`rounded-[14px]`, `p-[17px]`) — только классы из токенов и шкалы Tailwind
- Обязательные состояния интерактивных элементов: hover, focus-visible (глобальный стиль в `index.css`), active, disabled
- Один основной CTA на экран

## Правила
- Все новые компоненты — в отдельных файлах
- Типы выносить в `src/types.ts`
- Стили через Tailwind-классы, избегать инлайн-стилей (исключение — `--reveal-delay`)
- Данные только через SWR, прямые `fetch` не использовать (fetch-хелперы живут в `api.ts`)
- **Ключ SWR обязан описывать данные целиком** — все параметры, от которых
  зависит результат загрузчика. Иначе два разных объекта делят один кэш: у карточек
  встреч ключ состоял из книги и главы без `topic_ids`, и две встречи по одной
  главе (101 и 102) показывали одинаковые темы. Проще всего сериализовать
  сам аргумент загрузчика (`JSON.stringify(blocks)`), а не собирать ключ руками
- Обрабатывать состояния loading, error, empty
- Компоненты экспортировать как default
- Перед коммитом проверять сборку: `npm run build`
- Коммиты по Conventional Commits: `тип(область): описание` (типы: feat, fix, docs, style, refactor, test, chore)
- Название (описание) коммита — на русском языке
